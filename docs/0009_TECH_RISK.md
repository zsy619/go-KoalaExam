# ⚠️ 技术风险评估

> 全面梳理 KoalaExam 系统在高并发、安全、一致性、可用性、技术栈成熟度等维度的风险与缓解措施。

---

## 风险总览

| 等级 | 数量 | 主要类别 |
|------|------|----------|
| 🔴 高风险 | 6 | 高并发、数据篡改、身份伪造、单点故障 |
| 🟡 中风险 | 8 | 慢查询、缓存雪崩、阅卷异步、接口攻击 |
| 🟢 低风险 | 4 | 技术栈成熟度、团队学习成本 |

---

## 1. 高并发风险

### 1.1 考试开始瞬时并发

| 项目 | 说明 |
|------|------|
| **风险等级** | 🔴 高 |
| **触发场景** | 考试开始时大量学生同时登录、加载试卷 |
| **峰值** | 日常 100 倍以上（10000+ 并发 startExam） |
| **影响** | 服务响应慢 / OOM / 503 |
| **应对** | ① Redis 缓存预热（试卷组装结果提前 10 分钟加载到缓存） ② 负载均衡 + 水平扩展（3 实例 + Nginx upstream） ③ 限流中间件保护后端（基于 IP/用户 QPS） ④ CDN 静态资源加速 ⑤ 启动前压测验证 |

### 1.2 数据库连接池耗尽

| 项目 | 说明 |
|------|------|
| **风险等级** | 🔴 高 |
| **触发场景** | 高并发下数据库连接数不足导致请求阻塞 |
| **应对** | ① GORM 连接池调优：`MaxOpenConns=200`、`MaxIdleConns=50`、`ConnMaxLifetime=3600s` ② 慢查询监控（slow log > 200ms 告警） ③ 读写分离（主写从读） ④ 应用层连接等待超时设置 |

### 1.3 提交答案风暴

| 项目 | 说明 |
|------|------|
| **风险等级** | 🔴 高 |
| **触发场景** | 考试结束时大量学生同时提交 |
| **峰值** | 5000+ 提交 QPS 持续 3-5 秒 |
| **应对** | ① 阅卷异步化（使用 Redis Stream / Kafka 队列） ② 前端错峰提交（随机延迟 0-3s） ③ 提交接口限流（10 QPS/用户） ④ 阅卷 Worker 独立伸缩 |

### 1.4 阅卷任务堆积

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟡 中 |
| **触发场景** | 大量考试同时结束，阅卷任务激增 |
| **应对** | ① Worker 自动扩容（HPA） ② 队列深度告警（> 5000） ③ 失败重试 + 死信队列 ④ 优先保障客观题（主观题可延后） |

## 2. 安全风险

### 2.1 作弊风险

| 项目 | 说明 |
|------|------|
| **风险等级** | 🔴 高 |
| **触发场景** | 切屏、多设备、复制粘贴、替考等作弊行为 |
| **应对** | ① 全屏监控（`requestFullscreen`） ② 切屏检测（`visibilitychange`）+ 超限自动收卷 ③ 题目乱序 + 选项随机 ④ 行为日志审计（写入 ems_exam_record.audit_log） ⑤ 禁止复制粘贴（`copy/paste/contextmenu`） ⑥ 监考大屏（教师实时监控） ⑦ v1.2 加入人脸识别 + 屏幕录制 |

### 2.2 数据篡改

| 项目 | 说明 |
|------|------|
| **风险等级** | 🔴 高 |
| **触发场景** | 成绩、答案被中间人篡改 |
| **应对** | ① 成绩 `SHA-256(id|scores + salt)` 签名 ② HTTPS 全站加密 ③ 服务端答案校验（不允许客户端提交答案对比） ④ 操作审计日志 ⑤ 接口签名（HMAC-SHA256）防重放 |

### 2.3 身份伪造

| 项目 | 说明 |
|------|------|
| **风险等级** | 🔴 高 |
| **触发场景** | 冒名顶替考试 |
| **应对** | ① JWT + Refresh Token（短时访问 + 长期刷新） ② 可选：人脸识别 / 实名认证（v1.2） ③ IP 绑定（异常 IP 告警） ④ 设备指纹（Device ID） ⑤ 多端登录控制 |

### 2.4 接口攻击

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟡 中 |
| **触发场景** | 恶意刷接口、暴力破解、DDoS |
| **应对** | ① 限流中间件（IP/用户 QPS 限制） ② 验证码（登录/重置密码） ③ IP 黑名单（自动 + 手动） ④ SQL 注入防护（GORM 参数化 + WAF） ⑤ HTTPS 防窃听 |

### 2.5 XSS / CSRF

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟡 中 |
| **应对** | ① 输入过滤（bluemonday 库） ② CSP Header 限制脚本来源 ③ Token 而非 Cookie（天然防 CSRF） ④ SameSite Cookie（如用 Cookie） |

### 2.6 数据泄露

| 项目 | 说明 |
|------|------|
| **风险等级** | 🔴 高 |
| **应对** | ① 敏感字段加密（AES-256-GCM） ② 数据脱敏（手机/身份证） ③ 最小权限原则 ④ 数据导出审计 ⑤ 季度渗透测试 |

## 3. 数据一致性风险

### 3.1 答题进度丢失

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟡 中 |
| **触发场景** | 网络异常导致答题进度未保存 |
| **应对** | ① Redis 实时缓存 + 10s 定时同步 ② 断线续考（基于 record_id 恢复） ③ 客户端 LocalStorage 备份（双保险） ④ Service Worker 离线暂存（v1.1） |

### 3.2 并发提交冲突

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟡 中 |
| **触发场景** | 同一考试记录多人同时操作 |
| **应对** | ① 数据库唯一索引 `(exam_id, user_id)` ② 乐观锁 / 悲观锁 ③ Redis 分布式锁（提交/批改期间） ④ 状态机防止非法状态流转 |

### 3.3 事务一致性

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟡 中 |
| **触发场景** | 阅卷 + 错题入库 + 收藏 多表操作 |
| **应对** | ① GORM 事务（`db.Transaction(func(tx) {...})`） ② 失败回滚 ③ Saga 模式（异步场景） ④ 幂等设计（`INSERT ... ON DUPLICATE KEY UPDATE`） |

### 3.4 Redis 与 MySQL 数据漂移

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟡 中 |
| **应对** | ① Redis 答题进度是临时态，交卷时合并到 MySQL ② Redis 失败 → 降级 MySQL（30ms 仍可接受） ③ 定期对账（每日凌晨） |

## 4. 可用性风险

### 4.1 单点故障

| 项目 | 说明 |
|------|------|
| **风险等级** | 🔴 高 |
| **触发场景** | 服务宕机导致考试中断 |
| **应对** | ① 多实例部署（K8s Deployment 3+ replicas） ② 负载均衡（Nginx / SLB） ③ 健康检查 + 自动恢复 ④ 优雅退出（10s 排空 in-flight 请求） ⑤ PodDisruptionBudget 限制同时中断数 |

### 4.2 缓存雪崩/击穿

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟡 中 |
| **触发场景** | 大量缓存同时失效或热点数据失效 |
| **应对** | ① 缓存预热（考试前 10 分钟） ② 多级缓存（Caffeine + Redis） ③ 分布式锁（防止击穿） ④ 随机过期时间（避免同时失效） ⑤ 本地缓存兜底 |

### 4.3 数据库性能瓶颈

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟡 中 |
| **触发场景** | 慢查询导致服务响应变慢 |
| **应对** | ① 索引优化（EXPLAIN 分析） ② 读写分离 ③ 分库分表 ④ 慢查询日志 + 告警 ⑤ SQL 审计（CI 卡口） |

### 4.4 网络抖动

| 项目 | 说明 |
|------|------|
| **应对** | ① 重试机制（指数退避） ② 客户端重连（WebSocket） ③ CDN 兜底 ④ 多 Region 容灾（v2.0） |

## 5. 技术栈成熟度

### 5.1 Hertz 生态相对较新

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟢 低 |
| **说明** | 相比 Gin 等成熟框架，社区资源较少 |
| **应对** | ① Hertz 已在字节跳动内部广泛使用（高稳定性） ② 官方文档完善（cloudwego.cn） ③ hertz-contrib 仓库提供丰富的中间件 ④ 渐进式开发，先做 MVP ⑤ 关键路径用 Hertz，辅助工具可混合 Gin（不推荐） |

### 5.2 团队学习成本

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟢 低 |
| **说明** | 团队对 Hertz + Vue 3 组合式 API 不熟悉 |
| **应对** | ① 前期技术预研与培训（2 周） ② 参考官方 examples ③ Code Review + 知识分享 ④ 完善 Wiki 文档 ⑤ 内部技术沙龙 |

### 5.3 遗传算法的不确定性

| 项目 | 说明 |
|------|------|
| **风险等级** | 🟢 低 |
| **说明** | GA 组卷可能无法收敛或结果不稳定 |
| **应对** | ① 100 代内必收敛 ② 限制题目量（< 200） ③ 失败降级到随机策略 ④ 缓存常见试卷 |

## 7. 风险监控与告警

| 指标 | 阈值 | 处置 |
|------|------|------|
| 接口错误率 | > 1% (5min) | P2 告警 → 自动扩容 |
| P99 延迟 | > 500ms (3min) | P3 告警 → 检查慢查询 |
| MySQL 连接使用率 | > 80% | P3 告警 → 调连接池 |
| Redis 内存使用 | > 70% | P3 告警 → 清理或扩内存 |
| 阅卷队列堆积 | > 5000 | P3 告警 → 扩 Worker |
| 在线考试人数 | > 8000 | P4 通知 → 扩容预备 |
| 失败 JWT 签发率 | > 5% | P2 告警 → 密钥可能泄露 |
| 限流命中次数 | > 1000/min | P3 告警 → 可能有攻击 |

详见 [0011_RUNBOOK.md](0011_RUNBOOK.md) 应急响应流程。

## 8. 风险回顾机制

- **每月**：风险登记表更新（新增 / 关闭 / 等级调整）
- **每季度**：重大风险复盘 + Owner 调整
- **每年**：第三方安全审计 + 红蓝对抗
- **触发式**：发生 P0/P1 故障后强制更新本文档
